# ลำดับ UX การสมัครสอบ

## หลักการ

- นักเรียนไม่ต้องสร้างบัญชีและไม่ต้องล็อกอิน
- ใช้เลขประจำตัวนักเรียน + ชื่อ-นามสกุลเพื่อยืนยันกับรายชื่อปัจจุบัน
- ไม่ให้กรอกชั้น ห้อง หรือครูที่ปรึกษาเอง เพราะข้อมูลเหล่านี้มาจาก roster ที่เจ้าหน้าที่ตรวจแล้ว
- ระบบไม่เปิดรับสมัครจากหน้าเว็บจนกว่าเจ้าหน้าที่จะเปิด `registration_windows`
- ก่อนส่งต้องเห็นสรุปข้อมูลและยืนยันความถูกต้อง

## ลำดับหน้าจอ

1. **ข้อมูลสอบ** — เลือกปีการศึกษา สายการศึกษา และระดับธรรมศึกษา
2. **ยืนยันตัวตน** — กรอกเลขประจำตัวและชื่อ-นามสกุล ระบบตรวจซ้ำกับทะเบียนเมื่อส่ง
3. **ตรวจและส่ง** — แสดงสรุปข้อมูล ยืนยันความถูกต้อง และส่งใบสมัคร
4. **ผลการส่ง** — แสดงข้อความจาก RPC เช่น ปิดรับสมัคร, ตรวจข้อมูลไม่ผ่าน หรือบันทึกสำเร็จ พร้อมเลขอ้างอิงที่ไม่เปิดเผยข้อมูลส่วนตัว

## การแยกข้อมูลในฐานข้อมูล

ใบสมัครผูกด้วย `academic_year_id + student_id + education_band + dhamma_level`
โดย `student_id` ผูกกับ classroom ของ roster ซึ่งเก็บสาย ชั้น ห้อง และครูที่ปรึกษาแยกต่างหาก
จึงไม่ต้องใช้บัญชีผู้ใช้ของนักเรียนเป็นตัวแยกข้อมูล และรองรับนักเรียนคนเดิมย้ายจาก ม.ต้นไป ม.ปลาย
โดยถือเป็นคนละสายตามนโยบายโรงเรียน

## สถานะที่นักเรียนเห็น

- `REGISTRATION_CLOSED`: ยังไม่เปิดช่วงรับสมัคร
- `STUDENT_NOT_VERIFIED`: เลขประจำตัวหรือชื่อไม่ตรงทะเบียน
- `BAND_MISMATCH`: เลือกสายไม่ตรงกับทะเบียนปัจจุบัน
- `RULE_NOT_FOUND`: ยังไม่มีกติกาสำหรับปี/สาย/ระดับดังกล่าว
- `SUBMITTED`: บันทึกใบสมัครสำเร็จ

เมื่อบันทึกสำเร็จ ระบบแสดงรหัสอ้างอิงรูปแบบ `ปีการศึกษา-รหัสสั้น` ที่สร้างจาก UUID ของใบสมัคร
เพื่อใช้ตรวจสอบภายหลัง โดยไม่ใช้เลขประจำตัวหรือชื่อเป็นรหัสอ้างอิง

## การออกแบบสำหรับมือถือ

- ใช้ wizard ทีละขั้น ลดจำนวนช่องที่เห็นพร้อมกัน
- ปุ่มถัดไป/ย้อนกลับเต็มความกว้างบนจอเล็ก
- ใช้ `inputmode="numeric"` กับเลขประจำตัว
- ยืนยันซ้ำก่อนส่ง และรักษาข้อความสถานะไว้ในหน้าเดียวกัน
- สีและสถานะใช้เป็นตัวช่วย ไม่ใช้สีอย่างเดียวในการสื่อความหมาย
